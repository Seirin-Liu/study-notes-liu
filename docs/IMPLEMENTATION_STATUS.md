## 题库自动同步

网页仍每两秒同步。自动请求带上上次确认的文件版本，服务端先比较学科文件和设置文件的元数据；没有变化时只返回 `unchanged`。首次加载、文件变化和手动同步仍会完整读取并校验题库。只在磁盘上替换题图而不改题目记录时，可手动同步以重新校验题图。

## 编辑类别选择修复（2026-11-13）

类别下拉框仅在打开编辑器或切换学科时更新，并保留当前学科内的有效选择；修改题目、解析等文字不会清空类别。已验证选类别后继续编辑、切换学科，以及在隔离题库中保存类别到磁盘。

## 编辑题图（2026-11-15）

编辑器支持PNG/JPEG/WebP新增、替换、删除，最多20张、单张10 MB；保存时上传本地服务并同步正文位置标记。替换使用新文件名，删除仅移除引用，保留历史快照所需文件。已通过独立题库中的上传、替换、保存、移除及输入限制检查；当前浏览器自动读取超时，尚未做真实页面交互验证。

## 复制公式兼容（2026-11-16）

公式分隔符支持复制时重复转义的反斜杠，保存前规范化为标准分隔符；保留矩阵换行和真实语法错误检查。物理动量、动能、冲量共13组公式的行内及独立公式回归验证通过。公式错误使用中文字段名，保存按钮允许点击后提示原因并聚焦对应字段。

## 打印勾选顺序（2026-11-16）

打印预览和打印内容按勾选先后排序；取消后重新勾选排到末尾。全选当前结果不会打乱已有选择，只按列表顺序追加未选题；同步和筛选保持已有选择顺序。

## 图片插入与比例（2026-11-17）

每题图片独立管理并按“图片x-名称”排列。编辑区通过蓝色图片标记记录插入位置；标记可设当前栏宽 10%—100% 的比例，同图不同位置独立保存。新增图片不自动堆到题干末尾；旧题图标记继续兼容。图片预览支持本次待保存文件，正式保存仍使用本地资产接口，替换保留位置和比例，历史文件不删除。

`dist/image-references.js` 统一解析、替换、缩放和旧图兼容，`data-schema.js` 保留手动插入属性并剔除临时预览字段。`tests/image-references.test.mjs` 覆盖新旧协议、非法输入、临时预览、同图多处比例、通过本地 API 保存再读取，以及答案/解析/备注 8 种显示组合。具体浏览器交互和复杂图文分页仍应随界面改动验收。

## 前端源码模块化（2026-11-20）

原先 `dist/app.js` 是单文件，最长函数 `renderList()` 单行超过 3700 字符，改卡片样式要在整行里定位，回归风险高。现在源码拆到 `src/app/`，按职责分为 9 个模块：

| 文件 | 职责 |
| --- | --- |
| `00-core.js` | DOM 查询、图标、学科表、转义、共享状态、题库读写（`loadLocal`、`commit`） |
| `10-format.js` | 正文渲染：LaTeX 公式、题图位置标记 |
| `20-render.js` | 列表、学科导航、首页概览 HTML |
| `30-mascot.js` | 侧栏表情与动效 |
| `40-selection.js` | 状态/日期/类别筛选、逐题勾选、批量标记已掌握 |
| `50-editor.js` | 编辑面板、草稿、化学核查、打印设置同步 |
| `55-preview.js` | 打印预览联动、富文本字段定位 |
| `60-rich-text.js` | `**加粗**` / `__下划线__` 的插入与取消 |
| `70-boot.js` | 事件绑定与启动 |

构建方式：`npm run build` 或 `node scripts/build-app.mjs`，把 9 个文件合并回一个 IIFE 写入 `dist/app.js`，**浏览器加载方式不变**（仍是单个 `<script src="/app.js">`），所有模块共享同一闭包，不使用全局变量。

规则：**修改前端逻辑请改 `src/app/*.js`，不要直接改 `dist/app.js`**（构建会覆盖）。`tests/build.test.cjs` 会检查产物与源码是否同步，忘记构建时测试直接失败。

拆分已验证零行为变化：重构前后用无头 Chrome 对 7 个页面采集控件状态、卡片数量、预览输出与交互流程指纹，逐项比对完全一致，均无 JS 报错。

## 历史快照合并策略（2026-11-20）

**问题**：原先任何保存都会写一份整个题库的快照（约 27 KB）。勾选「已掌握」会写入 `mastered` 与 `updatedAt`，但题干、答案、解析完全没变，结果连续切换几次就产生多个内容相同的快照。实测 120 个快照中有 43 组相邻快照**仅掌握状态不同**，占 36% 体积。

**现在的规则**（`lib/store.mjs` 的 `writeSnapshot`）：

1. **内容变化一律保留快照**：题干、答案、解析、备注、方程式、题图、新增或删除题目、调整顺序，都会写一份修改前的完整快照。合并只针对状态变化。
2. **仅状态变化合并**：当本次保存与上一份快照只差 `mastered`/`updatedAt`，且上一份快照在 **10 分钟窗口**内，就跳过本次快照，沿用已有那份。窗口之外仍写新快照，避免把很久以前的状态一并吞掉。
3. **只改打印设置不写快照**（与原来一致）。

**效果**：实测「连续切换 4 次 + 批量标记 + 改解析 + 删除」在旧策略下产生 7 个快照，现在只有 3 个。日常勾选掌握不再增长历史文件。

**存量压缩**：`node scripts/compact-history.mjs --apply` 可把仅状态变化的冗余快照移入 `data/history-archive/`，**不删除**，需要时可随时移回。当前 120 → 77 个，3.2 MB → 1.9 MB；剩余相邻快照全部是内容变化，历史可恢复性不受影响。

**测试**：`tests/snapshot-policy.test.cjs` 覆盖 7 种场景，重点保证「内容修改、删除、新增绝不会被误合并」。
